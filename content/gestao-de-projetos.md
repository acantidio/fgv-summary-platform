## Slide 25

- Os Grupos de Processos da Gestão de Projetos

- INICIAÇÃO

- Define e autoriza o projeto ou uma fase do projeto.

- PLANEJAMENTO

- Define e refina os objetivos e planeja as ações necessárias para alcançar os

- objetivos e o escopo para os quais o projeto foi idealizado.

- EXECUÇÃO

- Integra pessoas e outros recursos para realizar o Plano do Projeto.

- MONITORAMENTO E CONTROLE

- Mede e monitora regularmente o progresso do projeto para identificar 
- variações em relação ao Plano do Projeto, de forma que possam ser tomadas 
- ações corretivas e/ou preventivas quando necessário para atender aos objetivos

- do projeto.

- ENCERRAMENTO

- Formaliza a aceitação do produto, serviço ou resultado e conduz o projeto ou

- uma fase a um final ordenado.

## Slide 31

- Métodos de Avaliação e Seleção de Projetos

- A decisão de investir em um projeto deve ser suportada por critérios objetivos. Os métodos abaixo são amplamente utilizados:

- VPL: Valor Presente Líquido

- TIR: Taxa Interna de Retorno

- Payback: Período de Retorno

- Calcula o valor atual dos fluxos futuros de caixa do 
- projeto, descontados a uma taxa de atratividade. VPL > 0 
- indica viabilidade financeira.

- Identifica a taxa que iguala os fluxos descontados ao 
- investimento inicial. Compara-se com a taxa mínima de 
- atratividade (TMA) da organização.

- Calcula o tempo necessário para recuperar o 
- investimento realizado. Simples e intuitivo, mas ignora 
- fluxos além do ponto de retorno.

- Scoring :Modelo de Pontuação

- Weighted Shortest Job First (WSJF)

- Critérios múltiplos são ponderados e pontuados (ex.: alinhamento estratégico, 
- viabilidade técnica, risco). Permite comparar projetos de naturezas distintas.

- Os projetos de maior valor (maior custo do atraso) com o menor esforço/duração 
- devem ser feitos primeiro

- representa uma definição cada vez mais detalhada do trabalho do
- projeto.

# Dinâmica — Project Model Canvas v2
### Dinâmica: Preenchendo o Project Model Canvas

Objetivo:
Nesta dinâmica, os alunos irão escolher um projeto de seu desejo e preencher as principais informações nas colunas do Project Model Canvas. O objetivo é ajudar os alunos a estruturar o projeto de forma clara, conectando as motivações e os resultados esperados, de forma que seja compreensível para todos os envolvidos.

Passos para a Dinâmica:

1. Escolha do Projeto (10 minutos)
Os alunos devem escolher um projeto do qual gostariam de trabalhar durante a dinâmica. Pode ser um projeto real de suas áreas de atuação ou um projeto fictício, como por exemplo um evento, um novo produto ou serviço, ou mesmo um projeto pessoal.

2. Preenchimento do Project Model Canvas (20 minutos)
Cada grupo de alunos irá trabalhar no preenchimento das seguintes colunas do Project Model Canvas para o projeto escolhido:

Gerente do Projeto: Defina quem será o gerente do projeto e quais serão suas principais responsabilidades. Podem escolher um membro do grupo para representar este papel.

Pitch: Desenvolvam uma breve descrição do projeto que comunique de forma clara e concisa o que é o projeto, quem será beneficiado e por que é importante. O pitch deve capturar o interesse dos stakeholders.

Justificativas: Respondam à pergunta: "Por que este projeto é importante?". Quais são os motivos que fazem esse projeto ser relevante para a organização ou para os stakeholders?

Objetivo SMART: Definam o objetivo do projeto utilizando a metodologia SMART (Específico, Mensurável, Atingível, Relevante e com Tempo definido). Este objetivo deve deixar claro o que o projeto pretende alcançar.

Benefícios: Liste os principais benefícios que o projeto trará para a organização ou para os envolvidos. Considere tanto benefícios tangíveis quanto intangíveis.

Produto: Descrevam o produto final do projeto, ou seja, o que será entregue ao final da execução. Pode ser um produto físico, um serviço ou um resultado específico.

Principais Requisitos: Identifiquem os requisitos principais que devem ser atendidos para que o projeto alcance seu objetivo e entregue o produto esperado. Considerem tanto os requisitos técnicos quanto os requisitos de negócio.

Resultado Esperado:
Os alunos vão desenvolver habilidades de planejamento, definição de objetivos e comunicação de projetos, praticando o uso do Project Model Canvas para estruturar as ideias principais de um projeto de forma concisa e bem-organizada. Isso ajudará a criar uma base sólida para qualquer projeto que venha a ser desenvolvido no futuro.

Resumo do Assunto:
O Project Model Canvas é uma ferramenta visual poderosa desenvolvida pelo professor José Finocchio para ajudar você a organizar e estruturar os principais elementos de um projeto. Ela facilita o alinhamento de ideias e permite definir os principais componentes do projeto de maneira clara e colaborativa. O Canvas foi desenvolvido como um modelo simples e eficaz para comunicar a essência do projeto em um único quadro visual.

O Project Model Canvas possui 15 campos, cada um com uma função específica para garantir que todas as informações importantes do projeto sejam consideradas. Esses campos, na ordem apresentada, são:

Gerente do Projeto: Defina quem será o gerente do projeto, indicando quem será o responsável pelo seu sucesso e condução.

Pitch: Desenvolva uma breve descrição do projeto que comunique de forma clara e concisa o que é o projeto.

Justificativas (Passado): Explique a razão pela qual o projeto é importante, incluindo os problemas que ele pretende resolver ou as oportunidades que visa explorar.

Objetivo SMART: Descreva o objetivo do projeto utilizando o conceito SMART (Específico, Mensurável, Atingível, Relevante e com Tempo definido), deixando claro o que o projeto pretende alcançar.

Benefícios (Futuro): Liste os principais benefícios do projeto, tanto tangíveis quanto intangíveis, explicando o valor que ele trará para a organização ou para os stakeholders.

Produto: Descreva o produto final do projeto, ou seja, o que será entregue ao final da execução. Pode ser um produto físico, um serviço ou um resultado específico.

Requisitos: Defina os requisitos principais que precisam ser atendidos para garantir que o produto ou resultado cumpra suas funções e satisfaça as necessidades do cliente.

Stakeholders Externos e Fatores Externos: Identifique todas as partes interessadas que estão fora da organização, como clientes, parceiros ou fornecedores, bem como fatores externos, tais como clima, pandemia, economia, leis, que podem influenciar este projeto.

Equipe: Defina a equipe que estará envolvida na execução do projeto, especificando papéis e responsabilidades de cada membro.

Grupo de Entregas: Defina as principais entregas do projeto, detalhando o que será realizado e quando.

Premissas: Liste as premissas que precisam ser consideradas como verdadeiras para o desenvolvimento do projeto, mesmo que não tenham sido comprovadas no momento.

Restrições: Defina as limitações do projeto, sejam elas relacionadas ao prazo, ao orçamento ou a qualquer outro recurso.

Riscos: Enumere os riscos principais que o projeto pode enfrentar e que precisam ser monitorados e mitigados.

Linha do Tempo: Estabeleça a cronologia do projeto, indicando os principais marcos e prazos para as entregas.

Custos: Estime os custos principais do projeto, ajudando a estabelecer um orçamento adequado para sua execução.

Com essa dinâmica, você terá a oportunidade de aprender a planejar de forma clara e prática, definindo os principais pontos que sustentam o projeto, como justificativas, objetivos, benefícios e requisitos. Com essa prática, você estará mais preparado para comunicar suas ideias e entender os elementos essenciais que fazem parte de um projeto bem-sucedido. Essa visão estruturada é essencial para garantir que todas as partes interessadas compreendam e se engajem com o projeto, contribuindo para sua efetiva realização.

# Dinâmica — EAP do Projeto v2
### Dinâmica:  Estrutura Analítica do Projeto (EAP), premissas e restrições

Objetivo:
Nesta dinâmica, vocês irão construir a Estrutura Analítica do Projeto (EAP) para um projeto escolhido, bem como premissas e restrições. O objetivo é ajudar a desenvolver uma compreensão detalhada de todas as partes do projeto, facilitando a organização e definição de entregas, atividades e responsabilidades de forma clara e estruturada.

O que é a Estrutura Analítica do Projeto (EAP)?

A Estrutura Analítica do Projeto (EAP) é uma ferramenta fundamental no gerenciamento de projetos. Ela consiste em dividir o projeto em partes menores e mais gerenciáveis, permitindo uma visão clara de tudo o que precisa ser feito para que o projeto seja concluído com sucesso. A EAP é geralmente organizada de forma hierárquica, onde cada nível representa um grau de detalhamento maior. Começa com o objetivo principal do projeto no topo e, à medida que vai descendo pelos níveis, as entregas e atividades são detalhadas até que sejam entendidas como componentes básicos de trabalho.

A EAP é crucial porque proporciona uma visão geral de todas as partes do projeto, facilitando a comunicação entre os stakeholders, o planejamento, a alocação de recursos e o controle do progresso. Ela também é uma base para definir as atividades e os prazos, permitindo que o trabalho seja monitorado e gerenciado de forma mais precisa e eficaz.

Passos para a Dinâmica:

1. Colocar o Nome do Projeto no Topo da EAP
Cada grupo deve começar colocando o nome do projeto que escolheram no topo da EAP. Esse nome deve resumir o propósito geral do projeto, como “Desenvolver um novo software de gerenciamento de clientes” ou “Organizar um evento corporativo”.

2. Subdividir em Grandes Entregas, incluindo o Gerenciamento do Projeto
Depois de definir o objetivo principal, cada grupo deve subdividir o projeto em grandes entregas. Lembrem-se de incluir não apenas as entregas relacionadas ao produto final, mas também os elementos de gerenciamento do projeto, como planejamento, controle e monitoramento. Pensem nas entregas como "blocos" importantes que precisam ser realizados para alcançar o objetivo geral.

3. Subdividir Até o Nível de Detalhamento Adequado
Para cada uma das grandes entregas, subdividam em componentes menores até chegar ao nível que seja possível definir claramente quem será responsável por cada atividade e quanto tempo levará para concluí-la com um certo grau de precisão. Por exemplo, se o entregável é “Desenvolver Interface do Usuário”, ele pode ser dividido em “Design de Layout”, “Codificação da Interface”, “Testes de Usabilidade”, etc. Dessa forma, vocês conseguem garantir que todas as atividades estejam detalhadas o suficiente para serem atribuídas e gerenciadas com eficácia.

4. Definir pelo Menos 2 Premissas 
Cada grupo deve definir pelo menos duas premissas para o projeto. Uma premissa é uma suposição que é considerada verdadeira para o planejamento do projeto. As premissas ajudam a estabelecer limites para o planejamento e definir expectativas. Por exemplo, uma premissa pode ser que “Os recursos necessários estarão disponíveis durante todo o projeto” ou “Os fornecedores entregarão os materiais dentro do prazo estabelecido”. Identifiquem as principais premissas que possam impactar o sucesso do projeto.

5. Definir pelo Menos 2 Restrições 
Além das premissas, cada grupo deve definir pelo menos duas restrições para o projeto. Uma restrição é uma limitação ou uma condição obrigatória que deve ser respeitada no projeto. As restrições podem ser relacionadas a tempo, orçamento, recursos, etc. Por exemplo, uma restrição pode ser “O orçamento do projeto não pode ultrapassar R$ 500.000” ou “O projeto deve ser concluído até dezembro deste ano”. Definir essas restrições ajudará a equipe a entender melhor os limites e as condições que devem ser respeitadas durante a execução do projeto.

Resultado Esperado:
Ao final da dinâmica, vocês terão uma EAP bem estruturada que fornece uma visão clara de todas as partes do projeto. Essa EAP servirá como uma base sólida para o planejamento, execução e controle do projeto, permitindo que a equipe veja claramente o que precisa ser feito, por quem e quando. Além disso, essa prática ajudará a desenvolver habilidades de organização, detalhamento de tarefas e comunicação eficiente dentro do contexto do gerenciamento de projetos.

Objetivo:
Nesta dinâmica, vocês irão trabalhar em um problema realista para aplicar os conceitos de gerenciamento da comunicação em projetos usando a metodologia de Aprendizado Baseado em Problemas (PBL). Podem ser problemas com comunicação entre a equipe interna, dificuldades para manter os stakeholders atualizados ou falta de clareza sobre responsabilidades e prazos. Muitos problemas podem surgir por falta de comunicação clara, levando a atrasos, má compreensão das expectativas e falta de alinhamento entre todos os envolvidos.

Problemas Hipotéticos para o Projeto:

Mudança nas Expectativas do Cliente: O cliente do projeto mudou suas expectativas em relação ao resultado, mas essa mudança não foi comunicada de forma clara para a equipe técnica, causando retrabalho e atrasos nas entregas. Falta de Alinhamento sobre Prazos com Fornecedores: Os fornecedores de materiais ou serviços não estão recebendo informações claras sobre os prazos do projeto, o que está resultando em atrasos e conflitos sobre entregas. Como melhorar a comunicação com os fornecedores para garantir que todos estejam alinhados?

Baixo Engajamento da Equipe do Projeto: Parte da equipe não está recebendo atualizações regulares sobre o andamento do projeto e, como resultado, não entende claramente suas responsabilidades e prazos. Como vocês garantiriam que toda a equipe esteja sempre informada e engajada no projeto?

Passos para a Dinâmica:

1. Análise dos Problemas de Comunicação 
Comecem analisando os problemas de comunicação acima. Identifiquem os principais pontos que precisam ser resolvidos para melhorar a comunicação no projeto e anotem suas ideias para ter uma visão clara dos desafios.

2. Proposta de Plano de Comunicação 
Depois de analisar o problema, desenvolvam um plano de comunicação para resolver as questões apresentadas no contexto do projeto escolhido. Usem o modelo "6W1H" como referência para estruturar seu plano. Esse modelo ajuda a garantir que todos os aspectos da comunicação sejam bem definidos:

Informação (What): Qual informação precisa ser comunicada? Ex.: cronograma, convite de lançamento, ata de reunião.

Propósito (Why): Qual é o propósito da comunicação? Ex.: acompanhar o progresso, informar sobre lançamento, obter aprovação.

Frequência (When): Com que frequência a comunicação deve ser feita? Ex.: semanal, diária, até 2 dias após a reunião.

Mídia (How): Qual será a forma de comunicação? Ex.: PDF, vídeo, áudio, mensagem, e-mail.

Onde (Where): Onde a comunicação será disponibilizada? Ex.: Intranet, redes sociais, e-mail.

Responsável (Who): Quem será responsável por realizar a comunicação? Ex.: Gerente de Projetos, Gerente de Marketing.

Partes Interessadas que receberão (Whom): Quem são as partes interessadas que devem receber a comunicação? Ex.: equipe, clientes, patrocinadores.

Utilizem este modelo para organizar seu plano de comunicação, garantindo que todos os aspectos sejam considerados para uma comunicação clara e eficaz.

3. Apresentação da Solução 
Cada grupo deve compartilhar seu plano de comunicação com os demais. Expliquem como o plano de comunicação ajudará a resolver os problemas identificados, quais stakeholders serão mais beneficiados e como a equipe vai garantir que o fluxo de informações seja mantido. O objetivo é ouvir outras perspectivas e receber feedback dos colegas.

Resultado Esperado:
Vocês terão a oportunidade de aplicar os conceitos de gerenciamento da comunicação ao projeto específico que escolheram, tornando o aprendizado mais contextualizado e relevante. Ao final, espera-se que vocês tenham desenvolvido uma visão crítica sobre como elaborar um plano de comunicação eficaz para seus projetos, identificando stakeholders, escolhendo métodos apropriados e garantindo um fluxo contínuo de informações. Essa dinâmica reforça a importância de uma comunicação bem planejada e executada para o sucesso de qualquer projeto.

# Dinâmica — Plano de riscos v2
### Dinâmica:  Análise dos Riscos em Projetos

Objetivo da Dinâmica

Capacitar os alunos na identificação e análise de riscos em projetos, aprimorando habilidades em desenvolver respostas adequadas aos riscos e em identificar melhorias em planos de mitigação. Os alunos deverão revisar uma matriz de riscos predefinida e analisar possíveis lacunas nas respostas, ajustando onde necessário para fortalecer o plano de gerenciamento de riscos.

Cenário

Imagine que vocês estão liderando um projeto de desenvolvimento de um novo software para uma empresa que atua no mercado financeiro. O objetivo é implementar um sistema que integre informações de diferentes departamentos, fornecendo maior agilidade e precisão na tomada de decisões estratégicas. O projeto envolve diferentes stakeholders e possui uma série de desafios técnicos, regulatórios e de segurança.

Riscos Positivos e Negativos e Técnicas de Respostas

Os riscos em projetos podem ser classificados em duas categorias principais: riscos positivos e riscos negativos.

Riscos Positivos (Oportunidades): São eventos incertos que, se ocorrerem, terão um impacto benéfico nos objetivos do projeto. Por exemplo, a descoberta de uma nova tecnologia que pode acelerar o desenvolvimento do projeto.

Riscos Negativos (Ameaças): São eventos incertos que, se ocorrerem, terão um impacto adverso nos objetivos do projeto. Por exemplo, a falha de um fornecedor crítico que pode atrasar a entrega do projeto.

Técnicas de Respostas aos Riscos

As estratégias de respostas aos riscos são ações planejadas para lidar com os riscos identificados e analisados. De acordo com o PMBOK, existem quatro tipos principais de estratégias de respostas aos riscos, que podem ser aplicadas tanto para riscos negativos quanto para riscos positivos:

Evitar: Eliminar a ameaça de um risco negativo ou proteger o projeto de seu impacto. Envolve mudanças no plano de gerenciamento do projeto, escopo, cronograma, custo ou qualidade para evitar que o risco ocorra ou afete o projeto.

Mitigar: Reduzir a probabilidade e/ou o impacto de um risco negativo a um nível aceitável. Envolve a adoção de medidas preventivas ou corretivas para diminuir a exposição ao risco ou sua severidade.

Transferir: Transferir a responsabilidade ou o impacto de um risco negativo para uma terceira parte. Envolve a alocação do risco para outra entidade que esteja disposta e capacitada a assumi-lo, mediante um acordo ou contrato.

Aceitar: Reconhecer o risco e decidir não tomar nenhuma ação proativa, mas monitorar o risco e desenvolver um plano de contingência caso ele ocorra.

Escalar: Transferir a responsabilidade do risco para um nível superior de gestão, onde ele pode ser tratado de forma mais eficaz devido a maior autoridade ou recursos disponíveis.

Para riscos positivos, as estratégias podem incluir:

Explorar: Buscar oportunidades de impactos positivos. Envolve a maximização da probabilidade e/ou impacto do risco positivo para garantir que ele ocorra.

Compartilhar: Entregar o risco para outro grupo que esteja mais bem preparado para lidar com a oportunidade. Envolve a colaboração com terceiros que possam aumentar a probabilidade de ocorrência do risco positivo.

Melhorar: Aumentar a probabilidade e/ou impacto de um risco positivo. Envolve a adoção de medidas para garantir que o risco positivo ocorra e que seus benefícios sejam maximizados.

Aceitar: Reconhecer a oportunidade e decidir não tomar nenhuma ação proativa, mas monitorar o risco e desenvolver um plano para aproveitar a oportunidade caso ela ocorra.

Escalar: Transferir a responsabilidade do risco para um nível superior de gestão, onde ele pode ser tratado de forma mais eficaz devido a maior autoridade ou recursos disponíveis.

Definição de Trigger

Um trigger (sinal de aviso) é um indicador ou evento que sinaliza a iminência de um risco. Ele serve como um alerta para que a equipe do projeto tome medidas preventivas ou corretivas antes que o risco se materialize. Por exemplo, um atraso de duas semanas nos relatórios de status pode ser um trigger indicando problemas na integração de sistemas.

Essas estratégias ajudam a garantir que os riscos sejam gerenciados de forma eficaz, minimizando as ameaças e maximizando as oportunidades para o sucesso do projeto.

2. Discussão e consenso (20 min)

Projeto a projeto, cada membro compartilha seu voto. Quando houver divergência, quem votou diferente explica o raciocínio. O grupo negocia até chegar a um consenso. Para cada projeto, registrem:

Valor: Alto ou Baixo

Esforço: Alto ou Baixo

Quadrante: Q1 / Q2 / Q3 / Q4

3. Posicionando no quadrante e definindo o portfólio (10 min)

Transfiram os projetos para o quadrante na folha de preenchimento. Depois, com o limite de R$ 800 mil e 2 projetos simultâneos, definam quais entram no ciclo.

Anotem o número do projeto dentro do quadrante correspondente.

Identifiquem quais do Q1 cabem no orçamento e na capacidade disponível.

Se sobrar orçamento, algum projeto do Q3 pode ser antecipado?

4. Apresentação e debate (5 min)

Cada grupo mostra seu quadrante e anuncia os 2 projetos do ciclo. O professor lança uma pergunta ao grupo: "O projeto 04 (IA) ficou em qual quadrante de vocês? Por quê?"
